# Flutter implementation checklist for backend content updates

Use [the change guide](flutter-backend-updates.md), [request examples](flutter-api-examples.md), and [OpenAPI](../../docs/openapi.yaml) as the contract. Backend implementation date: 2026-11-23; production deployment is not implied.

1. Extend shared models with nullable new scalar fields and empty-list defaults for new array fields. Keep `kind` values `project/product`, existing routes, and old response parsing. Add separate `project_type` and page status enums. Preserve the distinction between omitted fields, null and empty arrays in writes.
2. Add a page repository for GET `/admin/pages`, GET/PUT `/admin/pages/{page_key}`. Add a Website Pages screen with the fixed Home/About/Services/Projects/Contact keys. Missing pages can be initialized using the examples; page lists have no pagination.
3. Build typed section forms, section headings, SEO controls, a ready-media selector, and ordered featured-entry selection. Use the field limits in the change guide. Send complete `content` and `seo` objects on PUT. Keep IDs out of public display models. Refetch after save. Explain that saving a page as draft hides its current published version.
4. Extend Settings with navigation, footer, CTA, legal links, contact text and logo variants. Retain all original required fields. Replace each supplied link array as a whole; use visibility flags and order integers. Older clients may omit new settings fields without clearing them.
5. Extend the entry editor with project type, challenge, solution, outcomes, platforms, store links and SEO overrides. Keep existing category, technology, contributor and gallery editing. Null SEO overrides restore fallback behavior; responses contain the effective title/description.
6. Extend Services with features, cover, CTA and SEO. Add team-link visibility. Map recognized icon keys to local icons and handle unknown keys with a fallback.
7. Add media alt-text editing through PATCH `/admin/media/{id}` and optionally include `alt_text` during upload. Parse `alt`, `file_size`, and `display_mime_type`; retain original admin bytes/MIME fields. Handle nullable legacy file sizes. Poll upload status as before and handle in-use deletion conflicts.
8. Add inquiry `source_page` to the owner detail model. Keep `new/read/replied/archived` statuses. Do not send visitor analytics from the administrator application. SMTP settings and notification recipients belong on the server, outside public settings forms.
9. Verify login/token expiry, old records with no new metadata, missing/draft pages, hidden links, full-object page replacement, list clearing, publication toggling, draft featured references, ready/failed/deleting images, 422 field errors and 409 deletion conflicts. Avoid logging tokens or contact details.
10. Coordinate the Jaspr consumer separately: fetch page content plus settings during SSR, use reusable services/team/entry endpoints, render inline SEO, and keep existing loading/error/empty fallbacks. Test long content and missing images. Confirm actual staging URLs and inbox delivery after an authorized backend deployment.

Suggested instruction for the Flutter implementation agent:

> Implement the Flutter/shared-client changes described in these handoff files against the updated OpenAPI contract. Read the client directories' AGENTS.md instructions first, preserve existing API behavior, and make the new models and editors forward-compatible. The backend has added five fixed pages and extended existing content resources; do not invent `/projects` or `/site` API routes or change `kind` to platform names. Use the tested request examples, honor complete-object page PUT semantics, and run the client's relevant analyzer and tests. Report backend deployment assumptions separately from completed UI work.
